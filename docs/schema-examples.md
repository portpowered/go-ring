# Canonical schema examples

Run `go run ./tools/schemaexamples` to validate the canonical YAML or JSON documents under `api`. Use `-root` more than once when a canonical contract is split across directories or files. When a source manifest or base file identifies an assembled OpenAPI document, the validator uses its canonical sources and excludes the generated bundle as an owner. The repository's bundle-drift check must remain in the blocking `make check` path. References are resolved only from canonical local files; external references are rejected.

Every sample is synthetic and must be marked at its declaration site with `x-example-evidence: synthetic`. Put the extension beside a JSON Schema `example` or `examples` array, beside an OpenAPI Media Type `example`, and on each OpenAPI Example Object. For AsyncAPI, put each `examples[]` sample's evidence on its enclosing Message Object and direct payload-schema sample evidence on that schema; the closed Example Object does not take evidence. An OpenAPI Example Object must carry a local `value`; `externalValue` is not accepted. Samples are checked against their owning schema, including nested constraints and JSON encoded in strings with `contentSchema`.

For each OpenAPI request media schema, success response media schema, and failure response media schema, provide at least one sample on the media object or directly on its root schema. Root samples on locally referenced schemas and referenced OpenAPI Example Objects count. Nested property samples do not cover an operation group. Each AsyncAPI message with a payload schema also needs a message example or a direct payload schema sample. Every declared sample is validated even when another sample already covers the group. A group is not required when the media object or message has no schema.

Example Object references and JSON Schema references must resolve within the selected local files. Schema validation errors identify the document, pointer, and failing keyword without printing sample values.
