## Changes

- The account-scoped public client now uses explicit sessions and token renewal. HTTP, WebSocket, and FCM socket transports can be injected for offline testing.
- Device discovery returns one `Devices` slice. `GetDevice` returns a pointer to that model. Callers using the old family-specific slices must update their code.
- HTTP, signaling, FCM, and MCS wire contracts are schema-backed and checked against source call sites. Offline fixtures replay both requests and responses, including encrypted FCM events.
- CI blocks on all-rules golangci-lint, replay coverage, combined coverage, race tests, and generated-code drift.

## Guides

Start with [authentication](https://portpowered.github.io/go-ring/docs/guides/authentication/), [device operations](https://portpowered.github.io/go-ring/docs/guides/device-operations/), [client configuration](https://portpowered.github.io/go-ring/docs/guides/client-configuration/), and [push notifications](https://portpowered.github.io/go-ring/docs/guides/push-notifications/).

The protocol is not a stable public Ring API. Offline replays verify the documented fixtures; behavior can vary by account, device, and region.
